# 2. MVP 범위

MVP는 "HTS처럼 보이고, HTS처럼 화면을 다룰 수 있는 macOS 앱"까지를 목표로 한다. 실제 금융 거래 기능보다 화면 구조, 프로세스 구조, 확장 가능한 데이터 흐름을 먼저 확정한다.

## 포함 범위

- Electron 기반 macOS 앱 실행 및 패키징
- React 기반 HTS 워크스페이스 화면
- 관심종목, 차트, 호가, 주문, 뉴스, 계좌/잔고 패널
- 패널 드래그 이동
- 패널 최소화
- 패널 포커스 시 z-index 상승
- 레이아웃 초기화
- 데모 시세/호가/뉴스/계좌 데이터 표시
- 빌드 산출물 생성

## 제외 범위

- 실제 주문 전송
- 실시간 WebSocket 시세 수신
- 사용자 로그인
- 로컬 DB 영속화
- 클라우드 동기화
- 다중 물리 창을 사용자 설정으로 생성하는 기능

## MVP 완료 기준

- `npm run dev`로 개발 앱이 실행된다.
- `npm run build`로 macOS용 패키지가 생성된다.
- 첫 화면에서 주요 패널이 한눈에 보인다.
- 사용자가 패널을 움직이고 최소화할 수 있다.
- 다음 단계에서 데이터 연동을 붙일 위치가 명확하다.

## MVP 이후로 미루는 이유

실제 주문, 실시간 시세, 계좌 데이터는 모두 실패 비용이 높은 기능이다. 이 기능들을 UI 구조가 안정되기 전에 붙이면 데이터 흐름과 화면 상태가 뒤엉킨다. MVP에서는 사용자의 작업 방식과 화면 구성부터 검증하고, 이후 데이터 계층을 분리해서 연결한다.
