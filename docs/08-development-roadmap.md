# 8. 개발 단계별 로드맵

## Phase 0. 기준 정리

목표:

- 제품 방향과 MVP 범위 확정
- 프로젝트 문서 작성
- 현재 코드의 의사결정 근거 기록

작업:

- 프로젝트 개요 문서화
- MVP 범위 문서화
- 화면 목록 문서화
- Electron 프로세스 구조 문서화
- 멀티 윈도우 전략 문서화

완료 기준:

- `docs/project-plan.md`가 문서 진입점 역할을 한다.
- 화면 구현 전에 논의할 수 있는 공통 언어가 생긴다.

## Phase 1. UI MVP 안정화

목표:

- HTS형 워크스페이스 UI를 앱의 기본 경험으로 만든다.

작업:

- 패널 프레임 컴포넌트 분리
- 각 패널을 feature 폴더로 분리
- 패널 이동/최소화/포커스 상태 정리
- 좁은 창에서의 대체 레이아웃 정리
- 기본 키보드 접근성 보완

완료 기준:

- 화면 구성이 코드 구조와 일치한다.
- 패널 추가가 기존 코드를 크게 흔들지 않는다.

## Phase 2. 레이아웃 상태 저장

목표:

- 사용자가 배치한 화면을 앱 재실행 후에도 복원한다.

작업:

- 패널 상태 타입 정의
- 레이아웃 Store 분리
- 로컬 저장소 저장/복원
- 레이아웃 초기화
- 기본 프리셋 제공

완료 기준:

- 앱을 껐다 켜도 패널 위치와 최소화 상태가 유지된다.
- 잘못된 레이아웃 데이터가 있어도 기본값으로 복구된다.

## Phase 3. 데이터 계층 분리

목표:

- 데모 데이터를 실제 데이터 소스로 교체할 수 있는 구조를 만든다.

작업:

- Mock Market Data Service 작성
- 종목 선택 상태 Store 분리
- 관심종목/차트/호가/주문 패널 간 상태 동기화
- IPC 채널 이름과 타입 정의
- Preload API 초안 작성

완료 기준:

- `App.tsx`에 직접 박힌 데모 데이터를 제거한다.
- 패널은 데이터 소스가 Mock인지 실제 API인지 몰라도 된다.

현재 상태:

- Main Process mock snapshot 제공은 구현됨.
- Renderer Store 분리와 실시간 구독 모델은 아직 남아 있음.

## Phase 4. Electron IPC와 서비스 계층

목표:

- Renderer가 직접 외부 권한을 갖지 않는 구조를 만든다.

작업:

- `electron/ipc` 구성
- `electron/services` 구성
- Preload `contextBridge` API 정의
- Main Process에서 데이터 요청 처리
- Renderer에서 타입 안전한 API 호출

완료 기준:

- 데이터 요청 경로가 `Renderer -> Preload -> IPC -> Main Service`로 고정된다.
- Main과 Renderer의 책임이 명확하다.

## Phase 5. 실제 멀티 윈도우 실험

목표:

- 일부 패널을 OS 레벨 창으로 분리할 수 있는지 검증한다.

작업:

- `create-panel-window` 구현
- 패널 분리/붙이기 상태 모델 정의
- 분리 창 위치/크기 저장
- 분리 창과 메인 창 간 종목 선택 동기화
- 창 닫힘/재생성 처리

완료 기준:

- 차트 또는 호가 패널 하나를 별도 BrowserWindow로 분리할 수 있다.
- 메인 창과 분리 창이 같은 종목 상태를 공유한다.

## Phase 6. 실시간 데이터 연동

목표:

- Mock 데이터를 실시간 데이터 소스로 교체한다.

작업:

- WebSocket 연결 관리
- 재연결 정책
- 종목 구독/해제
- 시세 스냅샷 Store
- 장애 상태 UI

완료 기준:

- 관심종목, 차트, 호가가 같은 실시간 데이터 흐름을 공유한다.
- 연결 장애 시 화면이 멈춘 이유를 사용자에게 설명한다.

## Phase 7. 주문 기능 준비

목표:

- 실주문 전 단계의 안전한 주문 UX를 만든다.

작업:

- 주문 입력 검증
- 주문 확인 모달
- 주문 가능 금액 검증
- 주문 요청/응답 타입 정의
- 실패/성공 알림
- 주문 내역 패널 초안

완료 기준:

- 실제 API를 붙이기 전에도 주문 흐름을 끝까지 시뮬레이션할 수 있다.
- 주문 실행 계층이 UI와 분리되어 있다.

## Phase 8. 배포 품질

목표:

- 사용자가 설치해서 실행할 수 있는 macOS 앱 품질을 만든다.

작업:

- 앱 이름 정리
- 앱 아이콘 추가
- `package.json` description/author 보완
- macOS 코드 서명 준비
- 자동 업데이트 전략 검토
- 오류 로깅 정책 수립

완료 기준:

- DMG 파일이 제품 이름으로 생성된다.
- 기본 아이콘이 아닌 앱 아이콘이 적용된다.
- 배포 전 체크리스트가 문서화된다.
