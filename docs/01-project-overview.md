# 1. 프로젝트 개요

이 프로젝트는 macOS 데스크톱에서 동작하는 HTS(Home Trading System) 스타일의 작업 공간을 만드는 Electron 애플리케이션이다. 사용자는 하나의 앱 화면 안에서 관심종목, 차트, 호가, 주문, 뉴스, 계좌/잔고 같은 여러 업무 창을 동시에 보고 조작할 수 있어야 한다.

현재 기술 스택은 Electron, Vite, React, TypeScript다. Electron은 macOS 앱 패키징과 네이티브 창 관리를 맡고, React는 화면 내부의 HTS형 패널 UI를 담당한다.

초기 방향은 "진짜 증권사 HTS를 바로 복제"하는 것이 아니라, HTS형 멀티 패널 작업 환경의 뼈대를 먼저 안정적으로 만드는 것이다. 이후 실시간 데이터, 주문 API, 사용자별 레이아웃 저장, 다중 모니터 지원을 단계적으로 얹는다.

## 제품 목표

- macOS에서 자연스럽게 실행되는 데스크톱 앱
- 여러 업무 화면을 동시에 띄워 놓는 HTS형 작업 환경
- 패널 이동, 최소화, 앞으로 가져오기, 레이아웃 초기화 지원
- 향후 실제 시세/계좌/주문 데이터 연동이 가능한 구조
- 단일 화면 MVP에서 시작하되, Electron의 실제 멀티 윈도우 확장 가능성 확보

## 비목표

- MVP 단계에서 실거래 주문 실행
- MVP 단계에서 증권사 API 직접 연동
- 고급 차트 엔진, 보조지표, 백테스트 엔진 구현
- 사용자 인증, 권한, 감사 로그 전체 구현
- Windows/Linux 배포 최적화

## 기술 선택 이유

HTS형 앱은 브라우저 탭보다 데스크톱 앱에 가깝다. 창 관리, 로컬 저장, 다중 모니터, 네이티브 메뉴, 설치형 배포가 중요하다. Electron은 웹 기술로 빠르게 UI를 만들면서도 macOS 앱으로 배포할 수 있다는 장점이 있다.

초기에는 React 내부 패널로 시작한다. 진짜 멀티 윈도우부터 시작하면 IPC, 창 생명주기, 다중 모니터, 상태 동기화가 초반부터 복잡해진다. 제품의 핵심이 아직 검증되지 않은 상태에서는 화면 UX를 빠르게 검증하는 편이 낫다.

## 가장 조심해야 할 위험

- UI와 실제 주문 실행이 붙어버리는 것
- Renderer가 외부 API 키나 민감 권한을 갖는 것
- 패널 상태가 컴포넌트 내부에 흩어지는 것
- 처음부터 멀티 윈도우를 과하게 일반화하는 것
- 데모 데이터 구조가 실제 데이터 구조처럼 굳어지는 것

이 프로젝트는 "화면이 많은 앱"이 아니라 "상태가 많은 앱"이다. 장기적으로는 화면보다 데이터 흐름과 책임 경계가 더 중요하다.
